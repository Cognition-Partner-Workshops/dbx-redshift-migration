# Source-compatible foundation and SQL UDFs

## Deployment contract

`databricks/foundation/etl.sql` creates all ten bronze and silver Delta tables
and both `silver` UDFs. The foundation validation harness builds only that file;
the two standalone UDF scripts here are for independent function deployment.
Run them with catalog context `mig_redshift_dev` and profile `DEFAULT`.
The foundation asserts that catalog before any table/function writes.

The existing `Serverless Starter Warehouse` (`6dc4b80538621b7b`) in workspace
`https://dbc-c22a0245-3975.cloud.databricks.com` was used. No warehouse was created
and no production bundle was deployed. `make db-setup` uploaded the ten committed
CSVs to the development catalog's `bronze.raw` volume; no reset was run.

## Ingestion and type semantics

- Original column names, BIGINT/INT widths, VARCHAR limits, CHAR(4), DATE,
  BOOLEAN and DECIMAL(12,2) are retained. Redshift's timezone-free TIMESTAMP
  maps to TIMESTAMP_NTZ. Redshift distribution, sort and encoding clauses are
  replaced by Delta; bronze orders, order_items and web_events use liquid
  clustering on customer_id, order_id and customer_id respectively.
- Every row is loaded. There is no deduplication, filter, implicit date cutoff,
  or seed-specific transformation. Rerunning the foundation replaces tables;
  run it before downstream ETLs, which read silver and write gold.
- CSV parsing uses explicit schemas, headers, comma delimiters, double-quote
  escaping (including quoted JSON), the literal `\N` null sentinel, dates and
  timestamp_ntz formats, whitespace preservation and FAILFAST mode. Automatic
  schema evolution is disabled. CSV CHAR/VARCHAR fields are parsed as STRING
  and constrained by their destination DDL.
- SQL scripting resolves paths from `current_catalog()`. `read_files` rejects
  direct runtime expressions and local variables for its path; EXECUTE IMMEDIATE
  inserts the resolved path as a SQL literal. Backslash-escaped SQL literals
  preserve the CSV null sentinel and option quotes.
- CHAR(4) DDL alone returned `NE` and `SW` without padding on this warehouse.
  Silver customers/stores therefore apply `rpad(region, 4, ' ')` for every
  non-NULL region. Golden strings include `NE  ` and `SW  `; no tolerance was
  changed. Other columns retain their original DECIMAL scales and NULLs.
- Bronze campaign_touches.payload is VARIANT from parse_json. Silver retains
  the source JSON text from the same CSV because to_json(VARIANT) canonicalizes
  object-key order, breaking the foundation string oracle. This extra raw read
  preserves all rows and source text without joins on potentially repeated IDs.
  Attribution can use parse_json(silver.campaign_touches.payload). The volume
  should remain unchanged throughout a foundation run.

## UDF contracts

`f_clean_phone(p STRING) RETURNS STRING` uses `regexp_replace(p, '[^0-9]', '')`.
All non-ASCII-digit characters are removed. NULL returns NULL; leading zeros
are preserved; empty or punctuation-only strings return the empty string.

`f_fiscal_qtr(d DATE) RETURNS STRING` preserves the exact source body:

```text
'Q' || (((((month(d)::INT + 9) % 12) DIV 3) + 1)::STRING)
```

Databricks `/` performs floating-point division here; DIV preserves Redshift
integer arithmetic and prevents fractional or `.0` quarter labels. NULL returns
NULL. The source comment and requested February–April mapping disagree with
the body. `golden/finance_export/finance_monthly.csv` confirms February is Q4
and March is Q1. Source behavior, not the comment, is preserved:

| Month | Jan | Feb | Mar | Apr | May | Jun | Jul | Aug | Sep | Oct | Nov | Dec |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Quarter | Q4 | Q4 | Q1 | Q1 | Q1 | Q2 | Q2 | Q2 | Q3 | Q3 | Q3 | Q4 |

### Session authentication limitation

The configured DEFAULT profile uses Devin OIDC federation. No login or PAT is
needed. The CLI wrapper obtains a fresh ID token for every CLI call, but the
Python SDK needs DATABRICKS_OIDC_TOKEN in its own process. A single exported token
expired while polling the full SQL script. Validation was run with a local
Python startup helper outside the repository that refreshed that environment
variable every 10 seconds using `devin-oidc token --audience databricks`; values
remained in memory and were neither logged nor persisted. This helper is not
part of the committed project or its blueprint. Future long-running validation
sessions need equivalent OIDC refresh; the protected harness was not modified.
